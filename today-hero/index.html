웹 커스텀 카메라 구현 가이드

이 데모 페이지는 공유 편의상 단일 HTML 파일이지만, 실제 서비스에서는 아래처럼 React 컴포넌트로 구현합니다.

1. 카메라 스트림 획득 — getUserMedia

브라우저 표준 API로 카메라 스트림(MediaStream)을 얻는다. React에서는 마운트 시점에 useEffect로 호출하고, 받은 스트림을 ref로 잡아둔 video 엘리먼트에 연결한다.

useEffect(() => {
  let stream: MediaStream;
  (async () => {
    stream = await navigator.mediaDevices.getUserMedia({
      video: { facingMode: 'user' },
    });
    if (videoRef.current) videoRef.current.srcObject = stream;
  })();
  return () => stream?.getTracks().forEach(t => t.stop()); // 언마운트 시 카메라 해제
}, []);

2. 프리뷰 렌더링 — <video>

<video ref={videoRef} autoPlay playsInline muted /> 에 스트림이 흐른다. playsInline은 iOS Safari에서 전체화면 강제 전환을 막는 필수 속성.

3. 오버레이 UI — 일반 컴포넌트

video 위에 position: absolute로 겹치는 레이어는 전부 평범한 JSX다. 이 데모의 눈 스티커는 <img>, 문구는 스타일 입힌 텍스트, 드래그는 pointer 이벤트 핸들러. OS 카메라와 달리 촬영 UI를 서비스 디자인대로 만들 수 있는 이유가 여기에 있다.

4. 촬영 — <canvas> 합성

셔터는 "현재 비디오 프레임을 canvas에 복사"하는 동작이다. 오버레이 요소들도 화면 좌표를 canvas 좌표로 환산해 함께 그리면 합성 사진이 된다. canvas.toBlob()으로 Blob을 얻어 그대로 업로드(FormData)에 쓴다.

5. 화면 전환 — 컴포넌트 상태

촬영 화면 ↔ 결과 화면은 useState로 관리하는 일반적인 화면 상태 전환이다.

6. 예외 처리 (실서비스 필수)

  • HTTPS에서만 동작 — secure context가 아니면 API 자체가 차단된다.
  • 권한 거부(NotAllowedError) — 재요청은 불가하므로 설정 유도 UI가 필요하다.
  • 인앱 브라우저(카카오톡 등) — getUserMedia가 막힌 환경은 <input type="file" capture>로 OS 카메라 폴백.
  • 탭 이탈 시 스트림 정리 — track을 stop하지 않으면 카메라 사용 표시등이 계속 켜져 있다.
